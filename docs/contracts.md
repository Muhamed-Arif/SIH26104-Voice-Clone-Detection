## 2. DSP Audio Ingestion Contract (Member 2 -> Member 3)

DSP chunks must be submitted to `POST /api/v1/analyze` or streamed over `WS /api/v1/stream`.

### JSON Schema
```json
{
  "waveform": "dGVzdF93YXZlZm9ybV9ieXRlc19vcl9mbG9hdF9hcnJheQ==",
  "sample_rate": 16000,
  "chunk_id": "dsp-chk-88329-01",
  "quality": "HIGH",
  "timestamp": "2026-09-05T22:00:00.000Z",
  "session_id": "a576b92f-5b12-4c27-94d5-2a2ec9697dbb"
}
```

### Field Definitions
| Field | Type | Description | Constraint / Example |
| :--- | :--- | :--- | :--- |
| `waveform` | `string` or `number[]` | Base64 encoded audio bytes or float32 PCM samples | Non-empty |
| `sample_rate` | `integer` | Audio sampling frequency in Hz | `16000` standard |
| `chunk_id` | `string` | Unique chunk sequence identifier | e.g. `chk-0001` |
| `quality` | `string` | Estimated SNR / signal condition | `"HIGH"`, `"MEDIUM"`, `"DEGRADED"` |
| `timestamp` | `string` (ISO 8601) | Capture timestamp | UTC timestamp |
| `session_id` | `UUID` (optional) | ID of the active session context | If omitted, extracted from URL / Header |

## 3. ML Inference Client Contract (Member 3 <-> Member 1)

When the backend evaluates audio chunks, `services/ml_client.py` sends the DSP chunk payload to `ML_SERVICE_URL` (`POST http://localhost:8001/predict`) and expects the exact schema below.

### Output Prediction Format (from ML Service)
```json
{
  "synthetic_probability": 0.91,
  "confidence": 0.87,
  "model_version": "v0.3"
}
```

### Field Definitions
| Field | Type | Range | Description |
| :--- | :--- | :--- | :--- |
| `synthetic_probability` | `float` | `0.0` - `1.0` | Probability that audio is generated by voice cloning/TTS |
| `confidence` | `float` | `0.0` - `1.0` | Statistical certainty of the ML inference |
| `model_version` | `string` | e.g. `"v0.3"` | Deployed model version identifier |

## 4. Risk Engine & Assessment Specification

The Risk Engine maps `synthetic_probability` and `confidence` to a composite 0-100 score and categorical level:

### Categorical Risk Tiers
- **LOW Risk (`0 - 29`):** Action = `ALLOW`. Genuine human voice patterns detected.
- **MEDIUM Risk (`30 - 69`):** Action = `ALERT`. Ambiguous acoustic indicators; increased monitoring.
- **HIGH Risk (`70 - 100`):** Action = `BLOCK`. Confirmed synthetic cloning artifact. Dispatches prevention trigger.

### Standard Reason Codes
- `HIGH_SYNTHETIC_PROBABILITY`: Strong vocoder / diffusion model acoustic artifacts.
- `HIGH_CONFIDENCE_SPOOF`: Inference confidence exceeds certainty threshold.
- `MODERATE_SYNTHETIC_INDICATORS`: Borderline spectral anomalies observed.
- `LOW_CONFIDENCE_INFERENCE`: Unstable prediction dampens score toward uncertainty center.
- `DEGRADED_AUDIO_QUALITY`: High background noise or low SNR.
- `NATURAL_VOICE_CHARACTERISTICS`: Harmonic structure matches authentic human speech.
- `CONFIRMED_ANOMALY`: Multi-factor evaluation triggered automated flag.

#### 4. `WS /api/v1/stream?session_id={session_id}`
- **On Connect:** Server sends:
  ```json
  {"type": "CONNECTION_ESTABLISHED", "session_id": "...", "status": "READY"}
  ```
- **Client Frame:** Sends DSP Audio Chunk JSON.
- **Server Result Frame:**
  ```json
  {
    "type": "ANALYSIS_RESULT",
    "data": { /* Full AnalysisResultResponse */ }
  }
  ```
- **Ping / Pong:** Send `{"type": "PING", "timestamp": "..."}` -> receives `{"type": "PONG", "timestamp": "..."}`.

## 6. Database Schema (PostgreSQL / Alembic)

1. **`users`**: `id (UUID PK)`, `role`, `auth_metadata (JSON)`, `created_at`
2. **`sessions`**: `session_id (UUID PK)`, `user_id (FK->users)`, `start_time`, `end_time`, `mode`, `status`
3. **`model_registry`**: `model_id (UUID PK)`, `version (UNIQUE)`, `metrics (JSON)`, `threshold`, `deployed_at`, `status`
4. **`analysis_events`**: `analysis_id (UUID PK)`, `session_id (FK->sessions)`, `chunk_id`, `synthetic_probability`, `confidence`, `risk_score`, `risk_level`, `audio_quality`, `action`, `latency_ms`, `model_version (FK->model_registry)`, `created_at`
5. **`alerts`**: `alert_id (UUID PK)`, `analysis_id (FK->analysis_events)`, `severity`, `status`, `acknowledged_by`, `created_at`
6. **`audit_logs`**: `audit_id (UUID PK)`, `user_id (FK->users, nullable)`, `analysis_id (FK->analysis_events, nullable)`, `event_type`, `timestamp`, `action`, `outcome`
